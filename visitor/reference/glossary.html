Visitor glossary

Canonical language for this workspace. Lessons adhere to these terms.

Terms

Visitor: An object that encapsulates one operation across every element type.
Avoid: handler, processor (too vague)

Element: A member of the visited hierarchy that accepts visitors.
Avoid: node, shape (too narrow outside examples)

accept: The element-side entry point that routes to the matching visitor method.
Avoid: receive, dispatch (hides the handshake)

visit: The visitor-side method that implements logic for one concrete element type.
Avoid: handle, process (obscures the accept/visit pair)

Single dispatch: Method selection based on the runtime type of one object, the receiver.
Avoid: normal polymorphism (imprecise)

Double dispatch: Method selection based on the runtime types of two objects, element and visitor.
Avoid: multiple dispatch (broader than two)

Expression problem: The tension between adding new types and adding new operations to a hierarchy.
Avoid: extensibility problem (loses the type-vs-operation axis)

In this workspace, accept always means the element method and visit always means the visitor method. Promote a term here only once you can use it correctly — see Lessons 1–4.
